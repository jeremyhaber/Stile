# Sidebar v2.9 — move Chrome and the sidebar together; screenshots with annotation and S3 sharing

## A. Lockstep window moves and resizes (Mac app)

Feedback on 2.8: a small shift remains when moving; resize "takes a moment" (the resize lag was the rail height being fixed until the next rescan — fixed in RailFinder/OverlayController via `bottomInset`; keep that).

The remaining move shift is structural: macOS moves Chrome's window itself during a title-bar drag (no latency) while our panel follows a frame or two later. The fix is to drive the drag ourselves so both windows move from the same code path ("lockstep"):

- Setting `lockstepDrag` (default **on**), in the sidebar's Settings → App: "Move Chrome and the sidebar together" with note "Sidebar.app moves Chrome's window itself while you drag it, so the two stay together. Turn off if window snapping or other window tools misbehave." (`data-testid="app-lockstep"`, host message `setLockstep`, host state `lockstep`).
- **Moves**: in the existing CGEventTap (CloseInterceptor, or a new `DragController` sharing the tap), on `leftMouseDown` when Chrome is frontmost, the click is in a mapped, visible, non-little, non-fullscreen Chrome window, and the point is in Chrome's **draggable chrome area**: inside the window's top band (window.minY … contentTop, i.e. Chrome's toolbar row) AND the AX element at that point (`AXUIElementCopyElementAtPosition(appElement, x, y)`) is not interactive (role not in AXButton, AXTextField, AXTextArea, AXComboBox, AXPopUpButton, AXMenuButton, AXRadioButton, AXCheckBox, AXTab, AXLink, AXSlider, AXIncrementor, AXImage-with-press-action; walk up at most 3 parents checking for an `AXPress` action on a non-window element) → take over:
  - Swallow the mouse-down. Record start mouse location (global, top-left coords) and the window's start origin.
  - On each `leftMouseDragged`: target origin = start origin + (mouse − start mouse). Set Chrome's position via `AXUIElementSetAttributeValue(window, "AXPosition", …)` — this call is synchronous IPC and returns after Chrome has moved its window — then immediately move our panel(s) for that window with `setFrameOrigin` (no animation). Coalesce: if a set is still in flight when the next drag event arrives, only apply the latest. Swallow the dragged events.
  - On `leftMouseUp`: final set, swallow, end. If the mouse never moved more than 3 pt, it was a click: replay it to Chrome (post a synthetic mouseDown/mouseUp pair at the same location with `CGEvent` to Chrome's pid via `postToPid`, marked with a custom `eventSourceUserData` value so our tap ignores it).
  - Double-click (clickCount == 2) in the draggable area: don't take over; perform the title-bar double-click action (`AppleActionOnDoubleClick`: Maximize → press `AXZoomButton`, Minimize → `AXMinimized` = true, None → nothing) and swallow.
  - Keep the screen clamp: don't let the window's top go above the menu bar of the screen under the mouse (`NSScreen.visibleFrame` top).
  - macOS window tiling by dragging to screen edges won't trigger during a lockstep drag (documented trade-off).
- **Resizes**: when `leftMouseDown` is within the window's resize border (≤ 5 pt outside or ≤ 3 pt inside an edge; corners 10 pt) and not on the rail's own splitter → take over similarly: compute the new frame from the dragged edges (respect a minimum size of 500×350 pt and Chrome's AXMinimumSize if available), set AXPosition first then AXSize (only the ones that changed), then set our panel frame for the new geometry. Show the matching resize cursor while hovering edges? No — leave cursors to macOS.
- The predicted-frame following from 2.4 stays as the fallback path when lockstep is off or the drag started elsewhere (e.g. Mission Control, keyboard window managers).
- Never take over for little windows, unsupported/incognito windows, or when the overlay is disabled.
- Log one line per takeover start/end with the gesture type.

## B. Screenshots with annotation (extension)

### Capture
- **Visible area**: `chrome.tabs.captureVisibleTab(windowId, {format: "png"})`.
- **Full page**: inject a content script that measures the document (`scrollHeight`, `clientHeight`, devicePixelRatio), saves the scroll position, then for each viewport-height step: scroll, wait for two animation frames + 120 ms, ask the SW to `captureVisibleTab` (respect Chrome's limit of 2 captures/second → ≥ 550 ms between captures), and stitch into an `OffscreenCanvas` (in the SW or an offscreen document). After the first frame hide `position: fixed` / `sticky` elements (set `visibility: hidden` via a temporary style, restored afterwards) so headers don't repeat. Cap at 20 000 CSS px tall and the canvas limits (max 32 767 px per side, 268 M pixels); if capped, note it in the editor. Restore scroll and styles at the end (also on error/cancel). Show a small "Capturing… Esc to cancel" pill on the page while it runs.
- **Region**: first capture the visible area ("freeze", like Shottr), then inject an overlay showing that frozen image full-viewport with a dim layer and crosshair; drag to select a rectangle (live W×H label in px), adjust with handles, Enter or double-click to confirm, Esc to cancel, Space-drag to move the selection. Crop the frozen image to the selection.
- Pages where capture isn't allowed (chrome://, Web Store, PDFs viewer edge cases): toast "Screenshots aren't available on this page".
- Triggers: a camera button in the sidebar's address row (next to the Boost button, `data-testid="capture-button"`) opening a small menu (Visible area / Full page / Region / Recent captures); the page right-click menu "Screenshot ▸ Visible area / Full page / Region" (`chrome.contextMenus`, contexts page/image/link/selection); keyboard commands `capture-visible`, `capture-full`, `capture-region` in the manifest (suggested keys Alt+Shift+1/2/3 — Chrome allows at most 4 suggested keys total including `_execute_action`, so give suggested keys only to `capture-region`; the others are settable at chrome://extensions/shortcuts).
- Storage: captures (PNG blobs + metadata: page URL, title, time, mode, size) in the extension's IndexedDB, last 30 kept (older removed), never synced. Incognito captures are kept in memory only and discarded when the editor closes.

### After capture (setting "After taking a screenshot", `storage.sync.captureAfter`)
- **Open the editor** (default).
- **Show a thumbnail** (Shottr-style): a small floating card bottom-right in the page (injected, shadow DOM) with the image and quick actions Copy, Save, Edit (opens the editor), Upload (if configured); auto-hides after 6 s unless hovered.
- **Copy to clipboard only**: copy immediately and show a toast.

### Editor (`capture.html`, opened in its own popup window sized to the image, max 85% of the screen)
- Built from the user's existing annotation code (Tandem "Annotate image" bundle, provided as `/mnt/user-data/attachments/e0605526-dcdb-5d20-aaac-918c6d6e8268/a2b27be6-tandem-annotate-bundle.md`): **reuse `model.ts`, `history.ts`, `measure.ts`, `useAnnotator.ts`, `AnnotateStage.tsx`, `AnnotateToolbar.tsx`, `flatten.ts` and `annotate.module.css` as-is wherever possible** (keep their accessibility behaviour), replacing only the pieces that depend on Tandem: the Radix dialog shell (`AnnotateDialog.tsx`) becomes a full-window editor shell `CaptureEditor.tsx`; `replace.ts` / `useAnnotateImage.tsx` / composer integration are not used; missing shared imports (`ui/Dialog`, `preview.module.css`, toast helpers, `lazyNamed`) get small local replacements. Keep the bundle's tests for the pure modules (model, history, flatten) runnable with Vitest.
- Build: TypeScript + React compiled with **esbuild** into `extension/capture/dist/` (`capture.js`, `capture.css`), via `tools/build-capture.mjs` (`npm install` of esbuild, react, react-dom, typescript in a `tools/capture-build/` package; CSS modules via esbuild's `local-css` loader). The built files are committed so "Load unpacked" keeps working without a build step. Sources live in `extension/capture/src/` (excluded from nothing — fine to ship).
- Shottr-like layout: top toolbar with the export actions on the left (**Copy** ⌘⇧C — and plain ⌘C when nothing is selected, **Save** ⌘S, **Upload** if configured, **drag-out handle** that drags the PNG as a file into other apps via `DownloadURL`), the annotation tools in the middle (from `AnnotateToolbar`), zoom (Fit / 100% / +/−) on the right; the properties (colour, width, text size) appear as a small floating bar near the top-right only when a tool or shape is selected; canvas area with a checkerboard behind transparent edges; a status line at the bottom with size in px, mode, page title (link).
- Annotation is optional (setting "Annotation tools in the editor", default on): when off, the editor shows only the image with the export actions.
- Export uses `flatten.ts` (blur pixelation, crop) → PNG. Copy: `navigator.clipboard.write([new ClipboardItem({"image/png": blob})])`. Save: `chrome.downloads.download` (new `downloads` permission) to `Screenshots/Screenshot YYYY-MM-DD at HH.MM.SS.png` under the Downloads folder (setting: ask where to save each time, default off).
- Closing the editor keeps the capture in Recent captures; the sidebar's camera menu → Recent captures lists them (thumbnail, time, page) and reopens the editor.
- Theme: follows the sidebar colour (light/dark) and the 2.4 visual language.

### Upload to S3-compatible storage (optional)
- Settings → Screenshots → "Upload": provider presets (AWS S3, Cloudflare R2, Backblaze B2, DigitalOcean Spaces, MinIO/custom) that prefill endpoint format; fields: endpoint URL, region (default `us-east-1`, R2 `auto`), bucket, access key ID, secret access key, path prefix (default `screenshots/{yyyy}/{mm}/`), addressing style (path / virtual-hosted), file naming (random 10-char id + `.png`, default; or timestamp), **link type**: public base URL (e.g. `https://shots.example.com/`, link = base + key) or presigned link with expiry (1 h, 24 h, 7 days max). Buttons: "Test connection" (PUT a tiny `sidebar-test.txt` then DELETE it; show the exact error from the server on failure), "Clear credentials".
- Credentials stored in `chrome.storage.local` only (never sync), never sent anywhere but the configured endpoint. The settings page says so.
- Implementation: AWS Signature Version 4 in plain JS with `crypto.subtle` (HMAC-SHA256, SHA-256) — `PUT` with `x-amz-content-sha256` payload hash, `Content-Type: image/png`, optional `Cache-Control`; presigned GET via query-string SigV4 (`X-Amz-Expires`). Requests from the extension page/SW (host permissions cover CORS).
- After upload: copy the link to the clipboard, toast "Link copied", and show the link in the editor's status line with a "Copy link" button; remember the uploaded URL in the capture's metadata (Recent captures show a link icon).
- Tests: SigV4 against AWS's documented examples (the S3 "GET Object" presigned URL example with `AKIAIOSFODNN7EXAMPLE` / `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY`, bucket `examplebucket`, key `test.txt`, date `20130524T000000Z`, expires 86400 → signature `aeeed9bbccd4d02ee5c0109b86d86835f995330da4c265957d157751f604d404`; and the header-based PUT example from the S3 SigV4 docs if available); an e2e upload against a local fake S3 server (Node http) that verifies the signature with an independent implementation (or the same algorithm from a separate known-good library such as `aws4` installed for tests only) and stores the object; then fetch the returned link.
